# BACQ : Application-oriented Benchmarks for Quantum Computing
![](_images/logo_bacq.png)

## Global Description
Supported by the national program *MetriQs-France*, the BACQ project is dedicated to the development of an **application-oriented benchmark suite** for quantum computing in view of establishing a reliable, objective and long-lasting measurement instrument of the quantum computing practical performance.

To this end, a **multi-criteria** aggregation model *Q-MYRIAD* is proposed.
It establishes an explainable global performance score for the evaluated hardware based on the scores generated by the different metrics (hardware-agnostic or low-level hardware-dependent) and protocols proposed in the library.

The benchmark suite includes several classes of problems that cover four main quantum computing **application domains** of interest for industrial users:
- Quantum Physics Simulation
- Optimization
- Linear Systems Solving
- Prime Factorization

A particular focus is also set on benchmarking *energetic performance* of quantum computers.

Metrics are defined in order to address various quantum hardware, from NISQ machines to Fault-Tolerant hardware, and various paradigms (universal gate-based, analog devices, ...).

## Metrics Overview
- **Quantum Physics Simulation**
    - *Many-body Quantum Score (MBQS)*: based on a quench for the transverse-field Ising model [arxiv.org/abs/2601.03461](https://arxiv.org/abs/2601.03461)
    - *Low-level metrics*: Quench for the BCS model
- **Optimization**
    - *Q-score*: [MaxCut][1]
    - *G-score*: [Maximum Cardinality Matching on the $G_n$ series][2]
    - *Quantum WalkScore (QWS)*: Graph Pathfinding on cycle/2D-torus graphs
- **Linear Systems Solving**
    - *1-bit resolution*: Least square QUBO formulation
    - *Precision*: Laplace's equation (1D/2D) with VQLS
- **Prime Factorization**
    - *Number of bits*: Factorization problem
- **Energetic Performance**
    - *Metric Noise Resources (MNR)*: Energetic consumption with VQE.
    
[1]: https://ieeexplore.ieee.org/document/9459509
[2]: https://www.frontiersin.org/journals/computer-science/articles/10.3389/fcomp.2024.1286057/full
[3]: https://arxiv.org/abs/2601.03461

## Repository Structure
The repository `bacq/` is designed as a homogeneous and flexible structure for the integration of numerous application-oriented benchmarks, and the realisation of their protocol numerically or experimentally on quantum hardware.
It is composed as follows:
- `examples` contains a series of input files that correspond either to the description of a benchmark protocol, or to the description of experimental results from a specific benchmark protocol.
- `src/bacq_core` contains the core of the library, the scripts to launch a benchmark experiment/evaluation, a folder `hardware` containing files to define hardware-specific classes to run experiments on, and a folder `benchmarks` listing benchmark-specific scripts.

## Installing packages
**Clone the repository**
```bash
git clone https://gitlab.lne.fr/MetriQs-DEV-France/bacq.git
cd bacq
```

**Install the package**
In a virtual environment, install the bacq_core package
```bash
pip install bacq_core
```

Proceed the same way to install the relevant benchmark package (see their documentation).

## Run a benchmark
**From a protocol description** (i.e run with experiments on hardware)
1) Add your protocol input file in `examples`
    - e.g `protocol_seq_benchmarkname.json`.
2) Add (if necessary) scripts for your **specific hardware** in the `hardware` folder and ensure it is accounted for in the file `experiment.py` in the benchmark-specific folder of your selected benchmark:
    - Add `from bacq_core.hardware.my_hardware import MyHardwareClass`
    - Adapt or add relevant hardware in the `run()` function
3) Add (if necessary) scripts for your **specific algorithm** in the benchmark-specific folder and ensure it is accounted for in the file `experiment.py` in the benchmark-specific folder of your selected benchmark:
    - Add `from .my_algorithm_file import my_functions`
    - Adapt or add a `run_myhardware()` function
4) Finally, from a terminal
    ```bash
    python3 src/bacq_core/main.py protocol_seq_benchmarkname.json
    ```

**From existing experiment data**
1) Add your experiment data input file, e.g. `expdata_seq_benchmarkname.json`, in `examples/`.
2) From a terminal
    ```bash
    python3 src/bacq_core/main.py expdata_seq_benchmarkname.json
    ```

## Results recovery
For each problem instances, a metric and a success criteria are generated, and a score is computed as a result of multiple problem instances experiments.

Benchmark results (metric, success or failure of the criteria, score and relevant information) will be displayed (printed) for each problem instance at the end of the computation.
These benchmark results are also saved in a `result(s)_benchmarkname_devicename_experimentdate.json` file, acccording to a general format.

If experiments are performed in the process, an associated file is saved as `expdata_(seq_)benchmarkname_devicename_date.json`, in adequate format for benchmark evaluation.
